# 默认配置与用户设置升级

Bell 桌面模式的合并优先级为：**用户已有字段 > 当前默认 TOML > 代码兜底值**。源码使用工程根目录的 `config.toml`；打包版优先使用 exe 旁的 `config.toml`，没有时使用包内同名文件。仅当这些位置都没有默认 TOML 时，完全使用代码兜底。

## 升级时的处理

1. 读取 `%LOCALAPPDATA%\rw_creature_pet\settings.json`，按嵌套字段补齐缺失值。例如只缺 `[oracle.colors]` 中的一个颜色时，仅追加那个颜色。
2. 已有值均优先保留，包括关闭选项的 `false`、数量或概率的 `0`、精确小数和未在面板展示的参数。修改新版 TOML 的某个默认值不会替换用户已经保存的同名字段。
3. 合并后校验全部配置。仅当确实有新增字段时，先备份原文件为 `settings.json.bak`，再通过临时文件完整写入并原子替换。补齐后再次启动不会重复写入，也不会覆盖这份备份；之后用户主动保存设置时，备份仍按“上一次完整文件”的规则更新。
4. 自动写入失败时保留旧文件，本次继续使用合并后的用户设置，并在桌面启动时提示保存失败；不会因此重置成默认值。用户文件损坏、未知字段、无效值或不支持的文件版本仍会要求重新确认，确认保存前不覆盖原文件。

默认配置中的相对路径按 TOML 所在目录解析；已有用户相对路径仍按用户设置文件所在目录解析。自动补齐不会改写用户原有的路径字符串，也不会改写安装目录中的 TOML。

首次使用没有用户文件时，继续显示初始化设置，由用户保存后建立文件。`--config path.toml` 是显式的本次启动配置，不触发已有用户文件的自动升级；在设置面板主动保存时仍会保存当前配置。`SettingsStore.load()` 和 JSON 配色重载只在内存中补齐，自动落盘仅在普通启动流程执行。

## 设置面板的初始值

面板统一接收以上合并后的配置，不自行重新读取另一份默认值。全部普通控件，以及游戏目录、启动边缘和允许活动边缘，均在根目录 TOML 中明确提供初始值。

| 面板 | 默认配置来源 |
| --- | --- |
| 游戏目录 | `game_dir` |
| 常规 | `[desktop]`、`[interaction]`、`[audio]`，以及 `[oracle]` 的 `coarse_pixels_4x`、隐藏线缆、外发光设置 |
| 外观 | `[oracle].body_appearance` 主体外观、`outfit` 套装、`arm_scale` 机械臂缩放，以及 `[oracle.colors]` 的全部 17 种颜色 |
| 珍珠 | `[oracle]` 的矩阵、环绕、固定、卫星数量，矩阵避让和播放动画设置 |
| 投影 | `[oracle]` 的投影透明度、光环、电弧及拖动投影概率／冷却设置 |
| 移动 | `[desktop].screen` 选择显示器；`[oracle]` 的启动边缘、边上位置、允许边缘、活动带、速度与漫游设置 |
| 监视者 | `[overseer]` 的开关、最多 4 个独立配色/体型/触须数量槽位、随机/常驻方式、出现节奏、避让距离与换位概率 |

百分比字段在 TOML 中以 0～1 保存，在界面显示为百分数。数值控件按其显示精度展示，未编辑时保留配置原始精度。合法的高级数值超过面板常用范围时，控件会扩大范围以显示当前值，不把它钳制成另一数值。

“主体外观”默认 `bell`（手势之铃），显示 `[oracle.colors]` 配色，每行 3 项，与调试窗口共用配色字段及名称
`custom`（自定义迭代器）显示独立的 `[oracle.custom_colors]` 配色和 `[oracle.custom_appearance]` 尺寸参数；切换保留两边未保存的输入
机械臂缩放与附加套装仍是共用选项，配色切换不会重置位置、行为或珍珠
两种选择均随用户配置保存，旧配置缺少此字段时按默认值补齐
旧用户配置首次缺少 `custom_colors` 时，复制原配色作为自定义初始值并保存，后续不再从 Bell 同步覆盖
旧 TOML 缺少此组时也以该文件的原配色初始化；新增的默认 TOML 已分别列出两套颜色
“投影”页编辑当前主体外观的投影颜色，与对应外观页即时同步草稿，保存后才应用
恢复外观页默认设置会重置两套已展示的配色和自定义尺寸；恢复投影页默认设置仅重置当前主体外观的投影色及该页其他参数

绘制入口位于 `oracle/graphics/styles.py`：Bell 保留专用标记、耳机支架、念珠与逐倍率修正；自定义入口使用基础头脸、可编辑耳机和通用衣袍，不绘制 Bell 标记、侧点、支架和念珠
自定义标记和念珠颜色暂不展示，已有字段值继续保留；PNG 保留文件中的颜色，不受 Bell 标记颜色影响；新领口选项留待后续

### 自定义面部 PNG 与预览

选择“自定义迭代器”后可编辑“额头标记 PNG”和“面部装饰 PNG”两个独立槽位
每个槽位支持启用、导入、移除及 X/Y 偏移；使用 1× 静态 PNG，宽高各 1～32 像素，文件不超过 1 MB
保留原色、透明度和透明留白；图片中心对齐头部局部原点，X 正值向右、Y 正值向下，偏移范围 ±32 逻辑像素
默认额头 Y 为 -3，其余偏移为 0；图片随视线和头部旋转投影，并裁剪到头部皮肤轮廓
抬头时按头部高度逐渐改变纵向压缩：越靠头顶越强，下半张脸较弱；两个槽位共用头部坐标，透明留白不改变变形效果，正视和低头保持原投影
`oracle/graphics/face_decals.py` 中的 `UPPER_FACE_SCALE` / `LOWER_FACE_SCALE` 控制极限抬头时头顶 / 下巴附近的局部纵向比例，当前为 0.25 / 0.90
抬头时还会沿头部纵轴额外上移，幅度随抬头量平方增加；`UPWARD_EXTRA_LIFT` 控制最大额外位移，当前为 1.5 逻辑像素，叠加于原有最多 1.5 像素的视线位移
图层依次为皮肤、面部装饰、额头标记、眼睛；近侧耳机保持原有遮挡

配置分别存放在 `[oracle.custom_appearance.forehead]` 和 `[oracle.custom_appearance.face]`
字段为 `enabled`、`image_path`、`image_name`、`offset_x`、`offset_y`，旧配置补齐为关闭，不影响现有外观
相对路径以配置文件所在目录为准；GUI 导入后将规范化 PNG 副本存到用户设置旁的 `appearance/images/`，因此原文件搬走后仍能显示
副本按内容命名并复用，取消编辑不会写入配置，也不会修改桌宠，但已导入的少量素材副本可能保留
运行时贴图丢失会跳过该层；保存启用此层的自定义外观前需重新导入或关闭该层，Bell 不受影响

“面部预览”打开独立窗口，实时显示未保存的配色、头部长度、套装、PNG 和耳机编辑
提供正面、左右、抬头、低头以及睁闭眼检查，支持 1×/1.5×/2× 绘制精度；实际大小按物理像素显示，放大检查使用整数倍放大
64×64 逻辑像素画布为耳机预留上下及两侧空间，大型配件会自动扩展画布；放大检查使用同一帧的头图，去掉多余外圈留白
预览内的“面部贴图”“耳机部件”编辑页与外部设置共享草稿，导入、移除、开关及数值均双向同步；输入有效数值时即可更新预览
“保存并应用”复用主设置窗口的完整保存流程，会保存本次设置面板内全部修改；并非只保存当前耳机或贴图
关闭预览保留草稿，取消设置才放弃未保存修改；恢复外观页默认设置会同步重置两处控件
预览不会推进物理或自主行为，保存后才应用到桌宠；关闭设置时预览一起关闭
窗口较窄时采用上下布局，隐藏实际大小区域以给放大检查和编辑页留空间；编辑页独立滚动

### 自定义耳机

四个独立槽位为 `[oracle.custom_appearance.ear_body]`、`ear_part_1`、`ear_part_2`、`ear_part_3`
主体默认启用，三个配件默认关闭；旧配置按默认值补齐，原有 PNG 与配色不变，切回 Bell 时不使用这些部件

| 字段 | 含义 |
| --- | --- |
| `enabled` | 是否显示，配件可独立于主体启用 |
| `kind` | `ellipse` 椭圆、`rectangle` 矩形、`trapezoid` 梯形、`triangle` 三角形、`line` 直线、`png` 本地贴图 |
| `width` / `height` | 完整宽高，0.5～32 逻辑像素；直线使用宽度作为线宽、高度作为长度 |
| `offset_x` / `offset_y` | 以各自耳侧中心为原点，X 正值朝头部外侧、Y 正值向下，范围 ±32 逻辑像素 |
| `rotation` | 局部旋转角，-180～180°；左右镜像，右侧正值顺时针 |
| `tone` | `shell` 使用自定义附件底色、`highlight` 使用附件高光、`split` 使用两种颜色；不对 PNG 染色 |
| `image_path` / `image_name` | PNG 副本路径与原文件名，导入管理、尺寸和体积限制与面部 PNG 相同 |

PNG 导入后自动切换为贴图形状并将显示宽高设为图片像素尺寸，之后可调整宽高；切回几何形状时仍保留文件供再次选择
梯形上边为下边的一半宽，三角形默认尖端朝上，可通过旋转调整朝向；左右共用参数并镜像显示，随头部转向及旋转
同侧从后到前为主体、配件 1、配件 2、配件 3；远侧整组在脸后，近侧整组在脸前
耳机不使用面部裁剪，大型配件同步扩大绘制、清除旧像素和鼠标命中范围；相关 PNG 继续使用内存缓存，不逐帧读取磁盘

自定义尺寸保存后生效，切回 Bell 时恢复固定尺寸，自定义数据仍保留供下次切回使用
目前不提供多份预设管理

| 自定义字段 | 默认值 | 范围及效果 |
| --- | --- | --- |
| `head_length` | `1.0` | 界面显示逻辑像素，默认约 10.1px；保留颈部连接位置，沿头部局部纵轴调整长度；头饰随头顶移动 |
| `sleeve_root_width` | `6.0` | 袖根完整宽度，2～12 逻辑像素 |
| `sleeve_cuff_width` | `10.0` | 袖口完整宽度，2～16 逻辑像素；从袖根平滑过渡 |
| `robe_length` | `1.0` | 界面显示中央领口至中央下摆的理想长度，默认约 27.6px；保持肩部和 V 领区域，调整下半部长度及布料连接间距 |
| `sleeve_cuff_radius` | `2.0` | 袖口圆角半径，0～4 逻辑像素；0 为直角，实际半径受袖宽与袖长限制；手掌遮挡同步变化 |
| `neck_width` | `3.0` | 皮肤颈部完整宽度，1～8 逻辑像素；与自定义高领宽度独立 |
| `inner_robe_enabled` | `true` | 显示内搭；关闭后露出皮肤，保留已有高领参数 |
| `inner_collar_enabled` | `true` | 内搭启用时显示高领；关闭后保留平领口内搭 |
| `inner_collar_height` | `3.0` | 高领高度，0～8 逻辑像素；0 等同平领口 |
| `inner_collar_top_width` | `3.0` | 高领上口完整宽度，1～12 逻辑像素 |
| `inner_collar_bottom_width` | `4.0` | 高领下口完整宽度，1～12 逻辑像素 |

自定义内搭使用当前自定义配色中的 `inner_robe` 单色，基础平领口位于胸部质点沿身体轴向上 3 逻辑像素
高领下口随胸肩，上口随颈部方向，连接成可变形的梯形；身体倾斜、弯腰或倒立时沿用同一局部构造
内搭绘制和女仆围裙剪贴共用服装轮廓，关闭内搭后围裙不能画到露出的皮肤上；Bell 仍使用原有固定内搭，不受这些参数影响

头部和衣袍长度输入框保留一位小数，每次增减 1 逻辑像素，不包含当前显示倍率
衣袍自然摆动和下垂会改变实际屏幕轮廓，因此该数值按布料理想形状测量
内部与 TOML 继续使用 0.7～1.5 的比例字段，面板负责双向换算，已有用户配置无需迁移
未编辑时保留原始比例精度，保存其他设置不会因面板舍入而改变外观

尺寸调整不重建导航、行为或珍珠，改变衣袍长度时会更新布点并唤醒次级运动
恢复外观页默认设置也会重置这些尺寸草稿，包括当前被隐藏的一组；保存前不会改变运行中的人偶

显示大小支持 `1 / 1.5 / 2 / 3 / 4`。3× 放大 1× 像素，4× 默认放大 2× 像素；同一行的“使用更加狗啃的像素化效果”对应 `oracle.coarse_pixels_4x`，默认 `false`，勾选时 4× 改为放大 1× 像素。该选项仅在 4× 可操作，切换其他倍率会保留其值；单独修改它不会重置人偶姿态。工作区较小时仍保留原有的实际显示倍率上限，以容纳四边导航。

`desktop.screen` 默认为空字符串（自动跟随主屏幕）。在“移动”页选择实际显示器后，
GUI 将系统名称及设备信息保存为字符串，优先按厂商／型号／序列号匹配，
没有序列号时按系统名称匹配，不依赖屏幕枚举顺序。也可在 TOML 中直接填写系统屏幕名称。
保存后立即迁移人偶、底座、珍珠及桌面交互层，按所选屏幕的工作区和 DPI 换算坐标。
所选设备断开时暂用主屏幕，保留原配置；重新连接后自动返回。设置面板会保留“未连接”的选择，
修改其他参数不会覆盖它。若设备没有序列号且重新连接后系统名称改变，需重新选择一次。

## 保存与继续编辑

“保存并应用”写入用户配置并立即应用，保留设置窗口、当前分类与滚动位置；右侧的“保存并关闭”执行相同保存流程后关闭窗口
应用后可继续修改，“取消”或关闭窗口只放弃尚未保存的修改，不撤销已经应用的设置
校验、资源准备或保存失败时保留输入并显示错误，可以修正后重试；首次初始化仍使用“保存并启动”

## 恢复默认设置

- 窗口底部的“恢复全部默认设置”重置面板内全部设置项，包括顶部的游戏目录。
- 各分类顶部的“恢复本页默认设置”只重置该页的控件；“移动”页同时重置启动边缘、位置百分比和允许活动边缘。其他页尚未保存的修改会保留。
- 每次点击都重新读取当前默认 TOML，来源及相对路径解析规则与启动时一致。不从用户保存的 JSON 取默认值，也不修改 TOML。未在面板中展示的高级参数和托盘语言选择保持原值。
- 重置只修改本次表单，仍需“保存并应用”或“保存并关闭”（首次启动为“保存并启动”）后才会生效并写入用户文件；“取消”只放弃尚未保存的修改。默认模板读取失败时保留当前输入并显示错误。重置后的未编辑数值保留 TOML 原始精度。

拖动投影新增 `drag_projection_probability`（默认 `0.20`）和
`drag_projection_cooldown_seconds`（默认 `45.0`），旧配置按上述规则补齐。
设置页分别显示百分比和秒数；概率为 0 时禁用，不影响已有摆手或语音配置。

## 监视者槽位迁移

`overseer.appearance_mode` 为 `random` 或 `resident`，缺省继续随机出现；
`overseer.slots` 保存最多 4 个 `{ id, color, appearance, size, filament_count }` 对象，编号为 1～4 且不能重复
新增槽位或槽位条目未填写 `color` 时，默认使用白色 `#ffffff`，已有槽位配色保持原值

旧 TOML/JSON 只有 `overseer.color` 时，迁移为槽位 1，保留用户原配色；
用户 JSON 的迁移在补齐模板默认字段前执行，避免被模板配色覆盖
显式 `slots = []` 保持为空，不自动补回默认监视者
已有槽位时以各槽位颜色为准，顶层 `color` 仅兼容旧输入和单模型调试
旧槽位缺少 `size` 时继承顶层 `overseer.size`，不退回代码默认体型；保存后按槽位记录 0.5～1 的独立体型
`filament_count` 默认为 4，可设为 3～5，只控制普通外观；朋友？始终两条，并保留普通外观的数量设置供切回时使用
保存、取消和恢复默认仍遵循现有流程；只调整监视者不会重建人偶
