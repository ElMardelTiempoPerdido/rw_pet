# 角色升级、分享与备份

## 覆盖升级

1. 退出正在运行的桌宠
2. 建议先备份安装目录中的整个 `presets`，以及 `%LOCALAPPDATA%/rw_creature_pet/settings.json`
3. 下载发行 ZIP，将包内的 EXE、`presets` 和 `release.json` 合并复制到原安装目录，覆盖同名文件
4. 启动新版，保留原来的角色选择和本机设置

不要先删除原来的 `presets`，也不要只留下新版压缩包里的角色文件。当前角色配置、贴图及历史都在该目录中；更新包只提供发行角色的 `original` 恢复源

| 数据 | 首次从旧版升级 | 后续覆盖更新 |
| --- | --- | --- |
| 旧 settings 中现存角色的个人修改 | 迁入对应角色目录，尽量保留实际修改 | 不再重复迁移 |
| 未修改的角色参数 | 采用本次发行默认 | 保持已保存的当前效果 |
| `original` 恢复源 | 使用本次发行版本 | 更新为新版发行默认 |
| 自建角色、当前外观、角色历史 | 保留 | 保留 |
| 游戏目录、语言、屏幕、缩放、音量等本机偏好 | 保留 | 保留 |

更新后角色不会自动变成作者新调整的形象；希望采用新版形象时，可在设置中选择“恢复此角色默认值”，再按当前自动保存规则提交

首次迁移只为当前仍存在的角色各选择一份记录：优先上次正在使用的会话，再考虑与现存文件匹配的版本、路径及来源日期。历史版本、未关联会话、独立外观会话和已删除角色的旧记录只留在备份中，不重新出现在角色列表

原始旧 settings 和它引用的可用图片备份于 `%LOCALAPPDATA%/rw_creature_pet/migrations/characters-v1/`。若某角色迁移失败，错误中会标明角色；旧数据保留，修复缺失图片或写入权限后可重试，已经完成的角色不会重复生成

## 分享当前角色

在“设置 → 角色设置”点击“导出分享此角色”，选择 ZIP 保存位置，将生成的 ZIP 发给对方

- 导出读取当前表单草稿，关闭自动保存时也不必先保存
- 包含角色外观、行为、语音选择及所需 PNG，保留角色 ID
- 分享副本的当前设置和 `original` 都采用本次导出的效果，接收者恢复默认值也会回到这个效果
- 不修改本地当前配置、恢复源、角色选择或未保存状态，不增加本地角色副本
- 不包含历史、游戏文件、实际语音文件、游戏目录、屏幕和缩放等本机偏好

接收者在同一页点击“导入角色设置…”选择 ZIP，无需手动解压；也兼容旧版 JSON 和完整角色文件夹。导入时会将配置和图片安装到接收者的角色目录，之后可以删除下载的分享 ZIP

若本机已有同 ID 但内容不同的角色，明确选择一种处理方式：

| 选择 | 结果 |
| --- | --- |
| 使用导入版本 | 替换当前效果和 `original`，先在 `history/imports/` 备份原当前效果与恢复源 |
| 保留本地版本 | 继续使用已有本地角色 |
| 导入为新角色 | 分配新 ID，保留原本地角色 |
| 取消 | 不安装本次导入包 |

导入冲突不以日期决定胜负；较旧的包也可以明确选择使用。当前效果和恢复源都相同的重复包会复用本地目录

自动保存关闭时，导入后的场景应用等待“保存当前调整”或底部保存按钮；用户已明确安装的角色文件保留。替换或场景应用失败会回滚本次文件替换，并保留当前草稿

强烈建议通过按钮分享。自行打包完整角色目录虽然可以保留最新已保存效果，但不会包含未保存草稿，而且接收者的“恢复默认值”会采用目录中原有的 `original`，可能与首次显示的形象不同

## 备份与恢复

日常备份请保留整个 `presets` 和本机设置目录。仅备份 `settings.json` 已经不能备份角色外观与行为；仅备份角色根目录的 `profile.json` 也不够，它还引用了图片和历史文件

| 位置 | 用途 |
| --- | --- |
| `presets/profiles/<角色>/profile.json`、`appearance/`、`history/` | 当前角色及历史，应整体保留 |
| `presets/profiles/<角色>/original/` | 恢复默认值的完整来源 |
| `presets/profiles/<角色>/history/imports/` | 同 ID 替换前的角色与恢复源备份 |
| `%LOCALAPPDATA%/rw_creature_pet/settings.json` | 本机偏好、上次角色引用和迁移记录 |
| `%LOCALAPPDATA%/rw_creature_pet/migrations/characters-v1/` | 首次迁移前的原始旧配置和可用图片 |
| `presets/migration-archive/` | 早期误迁移角色的完整归档，不参与角色扫描 |

恢复完整备份时先退出程序，再将同一批次的角色目录和 settings 一起恢复，避免混用不同版本的引用。对历史导入备份，可通过“导入角色设置…”选择其中的完整角色文件夹；仍会经过同 ID 冲突确认

已有工作目录的当前文件损坏或缺失时，程序报告问题，不会自动用 `original` 覆盖。需要恢复早期误迁移的角色时，从归档中选择对应完整目录导入；清理说明见 [个人调整与外观历史](personal-adjustments.md#清理早期迁移生成的恢复角色)

若角色仍在原目录，但混入了旧配色或旧部件，可按 [纠正早期迁移选错的会话](personal-adjustments.md#纠正早期迁移选错的会话) 核对迁移指纹后修复，无需重置全部角色

## 开发验证

完整串联回归入口：

```powershell
python -m unittest tests.test_profile_lifecycle tests.test_release_package tests.test_profile_sharing tests.test_character_workspace tests.test_migration_cleanup -v
```

`test_profile_lifecycle` 在临时目录内生成旧版安装和 settings，实际生成并解压两版发行 ZIP，然后验证迁移、保存、重启、再次更新、外观历史及分享。接收端另起 Python 进程，发送端安装、原图、缓存和用户目录先被删除；接收端逐字段比较全部角色参数及 PNG 像素指纹，再验证删除分享包后重启与恢复默认值

此回归中的 EXE 是占位测试文件，用于验证打包和文件覆盖链路，不启动桌宠。实际交付物另行运行：

```powershell
python tools/packaging/verify_bell.py --exe dist/release/BellPet.exe --release dist/release.zip --report artifacts/profile-lifecycle-frozen.json
```

该命令检查实际 ZIP 的目录、引用资源及 EXE 一致性，从 ZIP 解压后的 EXE 启动，隔离本机用户配置并移除 Conda/Python PATH。它验证九个发行角色可读、首次选中 Bell、设置保存、资源初始化、ZIP 往返、桌面窗口、模拟、语言切换及音频解码与静音播放

本轮验收使用离屏 Qt，不等同于真实桌面上的逐项人工点击。实际语音和图集初始化使用了本机已安装的游戏资源；没有模拟所有用户的 DLC、权限和杀毒软件环境。以上验证不会修改正在使用的真实 settings 或角色目录

发行清单、发布作者新调整的 `--overrides` 用法及构建命令见 [发行打包](packaging.md)
