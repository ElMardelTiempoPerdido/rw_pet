# 个人调整与外观历史

## 自动保存

设置窗口底部的“自动保存修改”默认开启，属于本机使用习惯，不随分享文件导出

- 开启时，连续编辑合并约 650ms 后保存并应用；切换对象或关闭窗口前先处理待保存修改
- 关闭时，编辑保留在当前草稿；点击“保存当前调整”手动保存，或使用底部“保存并应用 / 保存并关闭”
- 关闭自动保存后，切换角色或关闭设置会丢弃未保存草稿；返回上次保存的个人调整，而不是作者默认值
- 从关闭改为开启时保存当前有效草稿；从开启改为关闭时不会清除已经保存的内容
- 保存失败保留草稿和当前选择，显示错误；自动保存失败时不会继续切换或关闭
- 游戏目录和资源尚未准备好的首次启动，仍须完成“保存并启动”

自动保存只提交当前角色的外观和行为字段，不会顺便保存音量、屏幕、缩放等本机草稿。本机设置继续使用底部保存按钮

已有游戏资源被复用，不因每个控件变化重新提取资源；改变外观时沿用桌面现有的外观更新路径，行为变化按原有逻辑重建相关场景

## 文件默认值与个人调整

| 数据 | 作用 |
| --- | --- |
| 文件默认值 | 首次载入该版本时，从分享文件复制并缓存；日常编辑不改写 |
| 个人调整 | 与默认值不同的字段，按文件类型、ID 和内容版本保存到本机 |
| 当前草稿 | 尚未保存的编辑、当前选择与外观历史变化 |

默认值、个人调整、当前对象及外观历史存放在本机 `settings.json` 的 `preset_state` 字段中，版本为 `2`；不混入共享 JSON，也不属于 `AppConfig` 的可分享字段

个人调整保存时，运行配置和编辑记录通过同一次原子写入提交。旧文件保留为 `settings.json.bak`；托盘单独保存配置不会清空编辑记录

旧版 settings 升级时，仅将原文件实际包含的角色行为字段作为 Bell 的个人调整，默认值来自发布包中的 Bell；用户确认后迁移一次，不迁移未发布的外观系统数据

同一 ID 的新版使用独立调整记录，不自动把旧版修改套到新版上；旧版记录保留。列表刷新不会替换正在使用的版本

## 角色拥有外观副本

外观细节页显示“正在调整：名称”。在角色设置页导入外观，只替换当前角色的副本，原外观文件保持不变

之后修改衣服、眼睛或配色，都属于当前角色的个人调整；切换到其他角色，再回来，仍使用该角色上次保存的外观与行为

始终保持一份角色设置被选中，不再维护独立外观的编辑会话。关闭自动保存时，未保存状态显示 `*`

## 最近外观

整体替换外观前，自动保存一份切换前的完整外观，包括已经做出的参数修改和贴图副本

- “恢复切换前外观”恢复最近一份
- “最近外观…”可选择最近 10 份快照，按时间排列
- 相同内容不重复保留，普通数值微调不会逐步生成快照
- 恢复历史只改变外观，保留当前角色的行为及本机设置
- 恢复时，当前外观也进入历史，可以再切回来
- 自动保存开启时，历史重启后仍可用；关闭时，只有手动保存才保留本次历史变化

贴图缓存位于本机配置目录下的 `appearance/images`，以内容摘要命名；默认外观和历史均使用缓存副本，移动或删除原分享文件不会破坏已经保存的历史

## 恢复默认值

- 右键参数选择“恢复此项默认值”，恢复当前角色文件提供的默认值
- 面部 PNG 偏移、耳机部件尺寸及单眼参数支持各自独立恢复，面部预览中使用同一入口
- “恢复默认外观”只恢复作者的外观，保留当前行为；恢复前的自定义外观会保留到历史
- “恢复此角色默认值”恢复该角色文件的外观与行为
- 本机字段始终恢复程序默认值；底部“恢复程序默认设置”从 TOML 重置可编辑参数，但不改变当前角色的主体类型

恢复默认值与恢复切换前外观不同：前者回到作者定义，后者回到你自己调整过的版本

## 再次分享

导出以当前实际外观和行为为准，这些值成为新文件的默认值，不携带个人调整和历史

“另存为新文件”创建独立身份；“更新已有文件”是明确重新定义该分享文件默认值的操作。日常自动保存不会调用它

从角色中单独导出外观，不会解除当前角色；将当前组合导出为新角色后，新角色的默认值就是导出时的效果
