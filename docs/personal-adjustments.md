# 个人调整与外观历史

## 自动保存

设置窗口底部的“自动保存修改”默认开启，属于本机使用习惯，不随分享文件导出

- 开启时，连续编辑合并约 650ms 后保存并应用；切换对象或关闭窗口前先处理待保存修改
- 关闭时，编辑保留在当前草稿；点击“保存当前调整”手动保存，或使用底部“保存并应用 / 保存并关闭”
- 关闭自动保存后，切换角色或关闭设置会丢弃未保存草稿；返回上次保存的个人调整，而不是作者默认值
- 从关闭改为开启时保存当前有效草稿；从开启改为关闭时不会清除已经保存的内容
- 保存失败保留草稿和当前选择，显示错误；自动保存失败时不会继续切换或关闭
- 游戏目录和资源尚未准备好的首次启动，仍须完成“保存并启动”

自动保存只提交当前角色的外观和行为字段，不会顺便保存音量、屏幕、缩放等本机草稿。本机设置继续使用底部保存按钮

已有游戏资源被复用，不因每个控件变化重新提取资源；改变外观时沿用桌面现有的外观更新路径，行为变化按原有逻辑重建相关场景

## 文件默认值与个人调整

| 数据 | 作用 |
| --- | --- |
| 文件默认值 | 角色目录的 `original/`，包含完整默认外观、行动参数和资源；日常编辑不改写 |
| 个人调整 | 角色根目录 `profile.json` 和 `appearance/` 保存完整当前设置，包含非当前主体的外观分支 |
| 当前草稿 | 尚未保存的编辑、当前选择与外观历史变化 |

本机 `settings.json` 的 `preset_state` 版本为 `3`，仅保存自动保存开关、角色引用和迁移状态；角色参数、默认值与历史不再重复保存在全局设置中

保存先生成不可变的外观和历史文件，再原子切换当前角色清单；settings 提交失败时回滚角色清单。旧清单保留为 `profile.json.bak`，成功提交后只保留当前及上一代文件；运行中的草稿、失败现场和用户资源不作为清理目标

旧版 settings 只为当前仍存在的角色迁移外观、行动、语音选择及该角色自己的外观历史。每个角色仅选一份记录，优先当前使用的会话，再匹配现存文件的版本和路径；其余取最近的来源版本。修改过的值优先保留，未修改的值采用新版发行默认

重复旧版本、未关联会话、独立外观会话和已删除角色的记录仅保存在迁移备份，不会生成额外角色。最老的全局单角色配置没有会话记录时，仍可保留其明确保存的参数

迁移前原始 settings 和引用图片备份在 settings 同级的 `migrations/characters-v1/`。逐角色记录迁移结果，失败保留旧数据并允许重试；完成后不再用旧快照覆盖当前设置。后续更新 `original` 只改变恢复源，不自动改变已有当前设置

## 角色拥有外观副本

外观细节页显示“正在调整：名称”。在角色设置页导入外观，只替换当前角色的副本，原外观文件保持不变

之后修改衣服、眼睛或配色，都属于当前角色的个人调整；切换到其他角色，再回来，仍使用该角色上次保存的外观与行为

始终保持一份角色设置被选中，不再维护独立外观的编辑会话。关闭自动保存时，未保存状态显示 `*`

## 最近外观

整体替换外观前，自动保存一份切换前的完整外观，包括已经做出的参数修改和贴图副本

- “恢复切换前外观”恢复最近一份
- “最近外观…”可选择最近 10 份快照，按时间排列
- 相同内容不重复保留，普通数值微调不会逐步生成快照
- 恢复历史只改变外观，保留当前角色的行为及本机设置
- 恢复时，当前外观也进入历史，可以再切回来
- 自动保存开启时，历史重启后仍可用；关闭时，只有手动保存才保留本次历史变化

已保存的图片均复制到角色目录，历史图片位于 `history/images`，以内容摘要命名；草稿仍可使用图片导入缓存，但保存后不依赖外部原图或全局缓存。角色目录是实际数据，应整体保留；删除或损坏当前文件会报错，不自动恢复默认覆盖用户调整

## 恢复默认值

- 右键参数选择“恢复此项默认值”，恢复当前角色文件提供的默认值
- 面部 PNG 偏移、耳机部件尺寸及单眼参数支持各自独立恢复，面部预览中使用同一入口
- “恢复默认外观”只恢复作者的外观，保留当前行为；恢复前的自定义外观会保留到历史
- “恢复此角色默认值”恢复该角色文件的外观与行为
- 本机字段始终恢复程序默认值；底部“恢复程序默认设置”从 TOML 重置可编辑参数，但不改变当前角色的主体类型

恢复默认值与恢复切换前外观不同：前者回到作者定义，后者回到你自己调整过的版本

## 再次分享

“导出分享此角色”将当前草稿中的外观、行动和语音选择写入 ZIP；这些值同时成为分享副本的默认值。保留当前角色 ID，收齐所需图片，不携带本机偏好和历史

分享只产生新 ZIP，不修改本地 `original`、当前选择或未保存状态，也不往角色列表添加重复副本。角色导出不再提供“更新已有文件”选项

从角色中单独导出外观，不会解除当前角色。同 ID 的不同角色分享包在导入时明确选择替换、保留或作为新角色安装；替换前的当前配置和默认值备份到该角色 `history/imports/`，失败时回滚

## 清理早期迁移生成的恢复角色

先退出正在运行的桌宠，执行只读检查：

```powershell
python tools/maintenance/cleanup_migrated_profiles.py --report artifacts/migration-cleanup-plan.json
```

确认检查结果后执行归档：

```powershell
python tools/maintenance/cleanup_migrated_profiles.py --apply --report artifacts/migration-cleanup-result.json
```

工具同时核对旧 settings 备份和角色中的迁移指纹，不按角色名称批量删除。确定为旧迁移生成的目录完整移到 `presets/migration-archive/`，原有角色保持不变，并清理 settings 中对应的引用；后续修改过的恢复副本也会连同最新内容归档

清理前的 settings 另存于本机配置目录的 `migrations/profile-cleanup/`。目录或 settings 在检查后发生变化会终止操作；设置提交失败会将目录移回。重复执行不会再次生成角色或移动已有归档

## 纠正早期迁移选错的会话

早期开发版本还可能把某角色的旧会话迁入原角色目录，表现为部分旧配色或部件覆盖新版，其余部件仍来自新版 `original`。归档多余角色不会自动纠正这些保留下来的目录；正常覆盖升级也不会重跑已完成的迁移

仅在核对这类问题时使用以下维护工具，执行前先退出桌宠：

```powershell
# 只读核对迁移指纹、原始备份和当前规则应选的记录
python tools/maintenance/repair_migrated_profiles.py --report artifacts/migration-repair-plan.json
# 备份全部当前角色和 settings，先在副本中修复并校验，再替换当前目录
python tools/maintenance/repair_migrated_profiles.py --apply --report artifacts/migration-repair-result.json
```

工具只处理能与旧 settings 备份对应的迁移指纹，不按角色名或配色猜测。默认比较错误迁移的预期结果、正确记录和当前设置，尽量保留迁移后的修改；确需放弃这些修改时可显式加 `--discard-post-migration`

完整备份位于 `presets/migration-repair/<时间标识>/before/`，同级 `settings.before.json` 保存修复前引用和本机偏好，`repair.json` 记录依据与结果。修复不改写 `original`，不处理未知来源角色，也不创建额外角色。使用不可变资源和原子清单提交，不移动角色目录；写入失败会恢复旧清单，修复完成后重复检查不再提出相同修复

回归入口为 `python -m unittest tests.test_migration_repair -v`，覆盖已有错误迁移结果、图片备份回退、迁移后调整保留、目录占用、多角色清单提交失败、settings 写入失败及重复执行
