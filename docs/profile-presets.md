# 角色设置与外观引用

**设置 → 角色设置** 是选择角色、新建角色、导入导出角色及外观的统一入口；其后的 **外观细节** 仅调整当前角色的外观参数

角色设置由行为参数和一份随包携带的外观组成，适合分享同一角色的外观及个性表现

覆盖升级、旧数据迁移及备份操作见 [角色升级与分享](profile-upgrade-sharing.md)

## 导出、分享和载入

1. 在各设置页调整角色行为，在“外观细节”页编辑外观，或在“角色设置”页导入外观
2. 在“角色设置”页点击“导出分享此角色”，选择 ZIP 保存位置；导出包含尚未保存的角色草稿
3. 分享生成的 ZIP；其中的当前设置与 `original` 都是本次导出效果，本地角色和恢复源保持原值
4. 接收者点击“导入角色设置…”选择 ZIP、旧版 JSON 或完整角色文件夹；ZIP 无需手动解压
5. 自动保存开启时，载入后保存并应用；关闭时先进入草稿，点击“保存当前调整”或底部保存按钮后生效

分享保留当前角色 ID，不生成或选中新角色，不携带全局设置、历史或机器路径。导出不要求先保存其他页签或填写有效的游戏目录。关闭自动保存时，载入后的场景应用仍等待保存；已明确安装的角色文件保留

强烈建议使用分享按钮收齐资源。手动完整打包目录仍可导入，加载其当前设置，同时保留包内原有 `original`；这与按钮导出的默认恢复源可能不同，但首次显示效果一致

默认存放位置：打包版为 EXE 同级的 `presets/profiles`，源码版为工程根目录的 `presets/profiles`；不受启动工作目录影响，也不会写入单文件 EXE 的临时解压目录

```text
BellPet.exe
presets/
  appearances/                       # 独立外观库
  profiles/
    profile-角色名-唯一目录后缀/
      profile.json
      character.json                  # 工作目录格式与角色 ID
      original/                       # 完整发行默认，普通保存不改写
        profile.json
        appearance/
      appearance/
        代次标识/
          appearance.json
          images/
      history/                        # 当前历史索引和历史图片
```

没有 PNG 引用时，不生成 `images` 目录

## 参数范围

以 [字段归属登记](preset-field-scopes.md) 为准，角色设置包含全部 `profile` 字段。旧格式外观只含当前主体分支，新工作目录的外观保留全部主体分支

- 行为包括鼠标观察与避让、拖动反应概率、漂浮和漫游速度、跨边与漫游概率、珍珠数量与行为、投影不透明度、光环大小及电弧数量等
- 底座速度、珍珠跟随范围和拖动反应概率均可在行为页调整；导入后保存、重新打开设置和再次导出均保留完整参数
- 控件显示的小数位数不影响未编辑参数的存储精度
- 本机字段保持不变，包括游戏目录、语言、屏幕与边缘限制、缩放、机械臂缩放、音量、自主行动和拖动总开关、线缆隐藏、外发光、光环/电弧显示开关及监视者设置
- 切换当前主体时，只更新它对应的外观分支；另一主体的配色和形态参数保留。附加外观与珍珠播放光晕颜色仍按现有规则作为共享外观字段载入

同版本文件缺失的行为字段使用代码定义的默认值补齐，不继承上一份角色参数或本机修改过的默认 TOML；未知字段、非行为字段、非法数值和不支持的格式版本会被拒绝

## 外观引用

`profile.json` 中的 `appearance` 同时记录外观 ID 和包内相对路径

```json
{
  "id": "外观的 UUID",
  "path": "appearance/appearance.json"
}
```

载入时始终读取这条路径指向的副本，并验证 ID 一致；不会到独立外观库寻找或替换成同 ID 的新版。因此，作者分享角色设置时的外观能随行为一起复现

- 导入外观或使用另一份角色设置时，导出副本保留外观 ID 和名称，但内容来自当前草稿，包含本次修改
- 没有外观来源时，导出自动创建新的外观 ID，并使用角色设置名称
- 在载入角色设置之后导入独立外观，行为参数保持不变，之后导出会引用新选择的外观副本
- 包内外观或 PNG 缺失、引用 ID 不一致时，整个角色设置载入失败，当前草稿保留；不会悄悄使用其他外观
- 图片导入可使用草稿缓存；成功保存后图片全部收进角色目录，不再依赖外部分享文件或全局缓存
- 两个柔性部件的开关、几何／PNG、前后图层、固定点和物理参数属于外观副本，随角色独立保存；关闭的槽位也保留参数及其图片引用

当前生效的参数保存在角色目录，启动时不自动跟随 `original` 更新。只有 `original` 的新安装包首次建立当前副本；已有当前文件损坏或丢失时报告问题并保留现场，不自动覆盖。完全空的库会创建默认 Bell；安装目录整体移动后，可按唯一对应的角色 ID 找回

## 个人调整与保存

角色设置拥有自己的外观副本和行为调整。外观细节页显示“正在调整：名称”；导入外观时，原外观先加入历史，新外观复制给当前角色。独立外观文件不会被日常修改反向更新

自动保存默认开启，短时间内的连续修改合并为一次提交，资源复用已有实例；关闭时，切换角色或关闭设置丢弃未保存的草稿。保存失败保留草稿和当前选择，可修正后重试

自动保存只提交当前角色的外观和行为，本机设置仍通过底部“保存并应用 / 保存并关闭”提交。首次启动需要先完成目录验证与资源准备

“恢复此角色默认值”恢复该文件原始的外观和行为；“恢复默认外观”只恢复外观；右键参数可单项恢复。外观历史保留近期 10 份完整快照，包括缓存贴图，重启后仍可使用

用户设置 JSON 顶层 `preset_state` 为版本 3，只记录自动保存开关、角色引用和迁移状态；角色的当前参数、默认值和历史均由角色目录提供，详见 [个人调整与外观历史](personal-adjustments.md)

完整规则见 [个人调整与外观历史](personal-adjustments.md)

## 重复版本

已有目录的列表仍按 ID 管理重复项：

- 同一 ID 使用 `updated_at` 最新的有效版本；文件系统修改日期不参与排序
- 日期相同时按路径稳定选择；无效新版本不会覆盖有效旧版本
- 小红字显示重复项路径，最新有效版本列在第一项；无效文件另行提示
- 刷新不替换当前草稿，必要时额外保留“已载入版本”；明确选择后才应用该版本

角色导入不依据时间戳决定版本。同 ID 的当前效果与默认恢复源都相同时复用已有目录；否则显示三个选择：

- 使用导入版本：先在 `history/imports/` 备份原角色和默认值，再替换当前设置及恢复源，原外观历史继续保留
- 保留本地版本：沿用本地目录
- 导入为新角色：生成独立角色 ID，保留已有角色

取消冲突选择不会安装导入包。替换或场景应用失败会回滚文件；较旧的分享包也可通过明确选择使用

## 格式与代码

`profile.json` 使用 UTF-8 JSON，顶层字段：

| 字段 | 含义 |
| --- | --- |
| `type` | `rw-creature-pet.profile` |
| `version` | 旧分享格式为 `1`，工作目录当前文件为 `2` |
| `id` | 角色设置 UUID，与外观 ID 独立 |
| `name` | 1～80 字符名称 |
| `updated_at` | 含时区的 ISO 时间戳，导出时为 UTC |
| `config` | 原配置嵌套结构，仅包含 `profile` 行为字段 |
| `appearance` | 外观 ID 与包内相对路径 |
| `state` | 版本 2 的历史索引相对路径，内容参与版本校验 |

包内的 `appearance.json` 沿用 [外观配置格式](appearance-presets.md)，可通过角色设置页的“导入外观到当前角色设置…”单独导入。资源引用不允许绝对路径、父目录跳转或链接逃逸

分享先在临时目录准备全部文件并重读校验，再生成 ZIP 并原子替换输出文件。独立外观仍保留原先的另存和更新入口；角色分享已移除覆盖本地文件的选项

- `presets/profile.py`：角色设置格式、范围校验、缺省值和配置合并
- `presets/profile_library.py`：角色设置导入导出与外观副本
- `presets/common.py`：外观与角色设置共用的元数据、字段操作、路径检查、目录扫描与发布
- `oracle/ui/preset_panel.py`：外观与角色设置共用的选择与文件操作
- `oracle/ui/profile_presets.py`：角色设置入口及外观来源提示
- `oracle/ui/settings.py`：草稿填入、预览和统一保存
- `presets/editing.py`：按字段归属比较内容、贴图像素指纹和来源记录
- `presets/personal.py`：文件默认值、个人调整及外观快照
- `presets/workspace.py`：角色工作目录、当前配置提交、恢复源和资源收纳
- `presets/migration.py`：旧 settings 备份、现存角色记录筛选、逐角色合并和迁移重试
- `presets/sharing.py`：可移植角色快照、ZIP、导入冲突与替换备份
- `oracle/ui/preset_workflow.py`：自动保存、当前角色归属和提交边界
- `oracle/ui/preset_controls.py`：保存开关、历史菜单及单参数恢复
- `oracle/ui/preset_dialogs.py`：角色导入冲突、外观另存和更新交互

## 首次启动、新建与旧版升级

- 首次启动选择发布包中的 Bell，通过固定角色 ID 识别，目录和显示名称可变
- 后续启动恢复上次角色及本机调整，角色下拉框不提供“未关联文件”状态
- `presets/profiles` 没有有效角色时，从程序默认 TOML 创建完整的 Bell 文件并选中；损坏文件不覆盖
- “新建角色…”填写名称后创建并选中一份通用自定义迭代器，不提供 Bell 等特殊绘制模板
- 新建外观采用 `presets/startup.py` 中的 `default_custom` 基底（来自 `appearance-default-4ec922f7e5b047178e3276ceaa735bee`）：浅灰肤色、白灰衣袍、关闭内搭与高领。基底已内置，不依赖外观库文件；已保存的角色默认值和个人调整不受影响
- “导入外观到当前角色设置…”弹出候选列表；选择候选或浏览外部文件不立即应用，点击“导入”才替换外观
- 外观导出不解除角色；导入只更新外观，行为、本机偏好和角色默认值保持原有归属

旧版 `settings` 在补默认值前记录原字段并备份，仅为当前仍存在的角色迁移一份有效记录。用户修改优先保留，未修改字段采用新版角色默认；额外旧版本、独立外观会话、未关联会话和已删除角色只留在备份中，不重建为角色目录

逐角色迁移可中断重试；全部成功后全局设置才切换为目录引用。早期版本误生成的恢复角色可以使用 [清理工具](personal-adjustments.md#清理早期迁移生成的恢复角色) 完整归档到 profiles 之外。发行包只带固定清单角色的 `original`，普通文件夹合并覆盖更新不会改写当前配置；构建与更新方式见 [发行打包](packaging.md)
