## 光环（圆环与短条）

默认显示两条细圆环及三圈各 10 / 30 / 60 个径向短条，参考 `OracleGraphics.Halo`。
三个短条环各自停留后平滑转动，填充长度独立变化。
单根短条达到目标且结束闪烁后，每帧以 1/60 的概率重选 0～1 的长度，追赶速度为
`1 / Lerp(2, 80, random)`；不再使用之前 2～8 秒的等待和窄速度范围。
按原版概率随机选一整圈伸长，再进行约半秒的短暂闪烁（三圈均可能被选中）。
中心圆环偶尔实心化，退出时从中央
挖空，最终恢复约 3 逻辑像素的环边；它不是整体透明度变化，也不额外生成人偶投影。
`expand`（0.8～2）和 `push`（−1～3）分别控制尺度及径向偏移，进入实心目标时也会
重选这两个参数。短条本身宽 4、最大长 8，不随常驻扩张变粗或变长。
保留桌面版较缓慢的环转动，暂不加入墙壁电弧。光环位于人偶、机械臂和珍珠后方，
使用独立的 1× 像素图层，和其他部件一样以最近邻缩放。

`config.toml` 的 `[oracle]`：

```toml
halo_enabled = true
halo_scale = 0.8           # 原版尺寸的倍率，允许 0.25～1.5
projection_opacity = 0.5  # 与珍珠字符共用；0 隐藏并停止光环更新
```

颜色共用 `[oracle.colors] pearl_glyph`，调试色块名称为“投影（珍珠/光环）”。
光环偏好的中心仍为头部沿颈部轴向外 20 单位；实际中心在安全区域中平滑跟随。
圆环及短条的全部外形保留在边缘活动带内，四角的帧间移动也不能切过中央。
最大范围按活动带厚度预留，小工作区先缩小基础尺寸，再限制扩张半径。空间充足时可达到
原版外圈短条中心 170 的理论最大半径（再乘基础和交互倍率），不再受旧的约 1.4 倍范围限制。
窄调试窗口的变化会小于实际桌面；中心使用固定的安全范围，扩张不会迫使中心反复位移。

调试窗口提供“光环”开关、“光环扩张一次”、“外圈闪烁一次”和“实心化一次”按钮。
实心化按钮只强制进入实心目标；退出与自然事件使用同一随机判断，不另设 2 秒倒计时。
按 40 Hz 计算，等待切回空心目标平均约 4.57 秒，但不是最低保持时间：可能很快退出，
也可能保持十几秒。完全填满前约半秒的过渡包含在这段随机等待中。
开关只影响当前预览，永久设置写入 TOML。
暂停时按钮记录反应目标，画面在单步或恢复运行后变化。场景重置会清除临时反应；
工作区重建将光环重新安置到有效区域，避免从旧屏幕位置插值穿过中央。

交互预留入口（只改变视觉，不接管或取消自主行为）：

```python
scene.pulse_halo(scale=1.25, hold_seconds=0.8)  # 短反应，结束后自动平滑恢复
scene.set_halo_scale(1.15)                    # 持续交互意愿
scene.set_halo_scale(1.0)                     # 平滑恢复普通状态
scene.halo.flash_ring(2)                     # 0/1/2：选定一圈短条伸长并闪烁
scene.halo.pulse_fill()                     # 进入实心目标、重选尺寸，之后自然随机退出
```

交互倍率允许 0.6～1.4；实际外形仍受空间上限限制。重复短反应替换当前反应，不累计放大。
它们与配置中的基础 `halo_scale` 相乘；短反应结束后回到持续意愿。当前只在调试按钮中触发，
没有把移动、观察或珍珠行为自动绑定到扩张，也没有桌面鼠标监听。

光环有独立随机流、视觉修订号和局部缓存，动画不唤醒停稳的身体/布料/线缆求解，
也不改变行为及眼睛的随机序列。开启光环时其动画会持续请求局部重绘；关闭光环或投影
透明度为 0 后，完全停稳且无其他动画时仍可停止主动重绘。
复现预览：`python tools/oracle/review_oracle_halo_details.py` 展示闪烁、实心化、挖空和更大扩张；
`python tools/oracle/review_oracle_halo.py` 的结果为 `artifacts/oracle-halo-poses.png`、
`oracle-halo-preview.gif` 和 `oracle-halo-debug.png`。

## 阶段 7：桌面模式

```powershell
conda activate rw_pet
cd D:\CODES\PY\rw_creature_pet
python run_pet.py --creature oracle --desktop
```

默认 1×，一个场景单位对应一个屏幕物理像素，系统 125%／150%／200% 缩放不额外放大人偶。命令行可加 `--scale 1.5` 等倍率，运行中也可在托盘菜单调整。工作区太小或倍率太大时，实际倍率会自动降低，为既有导航保留至少 640×480 场景单位；提示文字显示实际采用的倍率。

桌宠覆盖主屏 `availableGeometry()` 工作区，避开任务栏占用区，支持工作区非零或负数原点。Qt 顶层窗口位置使用全局逻辑像素（DIP），场景尺寸为 `工作区逻辑尺寸 × DPR / 实际倍率`，绘制缩放为 `实际倍率 / DPR`。保持四边滑动底座，身体与机械臂使用原有可达走廊，珍珠保留边缘曲线路径；活动带比例沿用 `oracle.edge_fraction`，默认 20%。桌面场景不使用调试配置的固定宽高，也不采用调试专用的固定底座模式。`--activity` 仍只控制蜥蜴的平地／爬墙模式。

透明、置顶、不抢焦点和鼠标穿透采用与蜥蜴共用的 `configure_desktop_overlay`。宠物可见像素及透明区域都不接收鼠标，所有操作通过任务栏通知区的 Bell 图标提供；图标可能在折叠的通知区中。

| 托盘操作 | 效果 |
| --- | --- |
| 暂停／继续 | 同时冻结或恢复自主行为、珍珠、身体、机械臂和次级运动；不积压物理时间 |
| 大小 | 调整屏幕物理像素倍率，重新建立有效位置，保持暂停选择 |
| 打开调试窗口（或双击托盘图标） | 暂停并隐藏桌宠，打开现有独立 Oracle 调试场景，复用已加载图集及字形；关闭调试窗口返回原桌宠 |
| 重置到边缘 | 按配置的初始边和底座比例重置，重新开启自主行为；保留暂停选择 |
| 退出桌宠 | 关闭桌宠和其调试窗口，停止计时器并移除托盘图标，退出进程 |

调试窗口不与桌宠共享仿真时钟，预览操作不会改动隐藏桌宠的行为；关闭调试后恢复之前的暂停选择。在调试期间主动勾选暂停，返回后也保持暂停。调试配色依然是临时预览，需要持久化时修改 TOML；桌宠下次启动读取该配置。本次没有改写用户 TOML 或外观尺寸。

### 分辨率、DPI 和工作区变化

监听主屏切换、可用工作区、屏幕几何、DPI 以及窗口的 DPR 变化；短时间连续信号合并为一次更新。同尺寸/DPI 的工作区仅改变原点时，移动窗口并保留当前仿真。尺寸或倍率改变时，在底座当前所在边附近重建场景，保留其边内位置比例；身体、头颈、机械臂、衣袍和连接线一起初始化，前后帧位置一致，丢弃旧坐标系中的路径与速度。

珍珠悬浮点按旧工作区的相对位置映射，再投到新的人偶跟随矩形与当前边缘走廊的交集，珍珠回到该悬浮点并保留字形。正在进行的观察重新回到停留，保留自主开关、随机流及完成计数。暂停选择独立于场景，重建不会擅自继续运行。主屏暂时不存在或工作区为空时，隐藏桌宠并暂停；有效工作区恢复后重新建立位置。旧屏幕的信号连接会解除，退出时也会清理待执行的重建任务。

帧率与调试窗口一致：物理 40 Hz、主动绘制最高 30 Hz。复用人偶／线缆绘制缓存，珍珠独立绘制；静止无视觉变化或暂停时不主动重画画布。软线仍采用先前允许局部越界的方案，屏幕外沿由窗口裁剪。

### CPU 加速与绘制缓存

在 `rw_pet` 环境中安装可选加速依赖：`python -m pip install -e ".[speedups]"`。
当前设备已安装 Numba。`[oracle]` 可添加 `physics_backend = "auto"`（默认），
也可设为 `"python"` 进行对照，或 `"numba"` 强制使用编译内核。重启后生效。
`auto` 在缺少依赖或编译不可用时回退；显式 `numba` 会报告错误。
诊断还可用环境变量 `RW_PET_NUMERIC_BACKEND` 覆盖该选项。

首次启动会在场景创建时编译线缆约束内核，之后复用磁盘缓存。两种后端使用同样的
双精度、求解顺序、迭代容差和休眠条件；没有降低物理帧率、节点数量或珍珠数量。
机械臂截面参数、衣袍领口采样和颜色预先缓存，身体绘图指令以子层引用复用。
桌面窗口只刷新新旧外形覆盖的区域；外形稳定后缓存透明位图，头部与珍珠仍独立更新。
调试窗口继续用矢量指令，以便任意放大检查。当前尚未启用 GPU 后端。

诊断入口：`python tools/oracle/profile_oracle_current.py`；增加
`--desktop-seconds 12` 会显示并自动关闭真实桌面测试实例，增加 `--desktop-idle`
可测人偶静止、珍珠继续运动的开销。使用 `--output-prefix 名称` 保留不同版本的报告。
基线与本轮结果见 [性能记录](performance-2026-09-26.md)。

## 固定悬浮珠与卫星珠

最初额外创建的调试单珠已移除，所有可见珠子都由各组的配置数量决定。当前本机配置保留用户的矩阵 7、内圈 4、外圈 2，新增固定珠 2、卫星珠 1，总计 16 颗；没有再额外加一颗观察珠。固定珠包含作为卫星母珠的那几颗，母珠不另计数量。

在 `[oracle]` 中配置，重启生效；调试窗口也有“固定 / 卫星”数量输入框用于临时预览：

```toml
pearl_fixed_count = 2      # 0～32；完整原版布置为 11
pearl_satellite_count = 1  # 0～32；完整原版布置为 5
```

固定珠为 0 时，卫星也不生成，不会为了放置卫星偷偷补母珠；卫星数量配置仍保留，重新开启固定珠后恢复。所有固定珠和矩阵关闭时，观察动作安全跳过，漂浮、漫游和冥想照常进行。关闭所有珍珠后没有隐藏的占位珠。旧诊断脚本中的 `scene.pearl` 仅作为首颗正式固定珠的只读别名，没有固定珠时返回 `None`。

### 桌面适配

固定珠沿用“附近保持悬浮点，超出跟随矩形或换边后更新悬浮点”的滞回逻辑。每棵卫星树由自己的母珠运动引导，二级卫星跟随真实一级卫星位置，双卫星保持等相位。狭窄活动带会按整棵树的最大延伸半径统一缩小该族轨道，预留珠体及字符投影；母珠规划时就包含所有子珠的安全余量，子珠不单独夹边，也不逐帧规划路线。普通卫星桌面速度为 1.2°/tick，42 半径的慢卫星保留 0.8°/tick。

超过原版 5 颗卫星时重复三种组合，分配到现有固定珠；同一母珠的同级同半径卫星均匀分布。默认 1 颗对应单卫星组合。固定珠按 3∶4∶4、卫星按 2∶2∶1 分配三档色，继续使用确定的最大余数取整；恢复 11 / 5 时恢复原版配色和母子关系。原有配色和线缆节距没有改动。

## 可选珍珠矩阵

固定珠、卫星、矩阵与环绕珠的字符投影共用 `[oracle] projection_opacity`，默认 `0.5`（半透明）。范围 `0`～`1`：`0` 隐藏字符，`1` 完全不透明；仅作用于投影，珍珠本体、角色与机械臂不变。该配置也供后续光环使用，本轮尚未添加光环。修改 TOML 后重新启动生效，调试和桌面模式一致。透明度进入现有字形缓存，不逐帧重新生成贴图。

调试窗口勾选“珍珠矩阵”，或在桌面托盘菜单中勾选同名选项即可开启。默认关闭，开关不打断自主行为、现有单珠观察或暂停状态；重置和桌面工作区/倍率改变后保留本次选择。调试窗口是独立场景，从桌面打开时继承开关，之后两者互不修改。运行中的开关不写回配置；若希望启动即开启，在现有 `config.toml` 的 `[oracle]` 表内添加：

```toml
pearl_matrix_enabled = true
```

矩阵数量设为 14 时保留原版 `Oracle.SetUpMarbles` 的斜向 3×5 缺一格布局；常规场景间距 17，每颗使用稳定的独立字形。颜色保持原版的槽位分配：12 颗共有色，零起算槽位 `(2,0)`、`(1,3)` 两颗为辅色；固定珠、卫星与环绕珠各自按比例分配三档色。

### 抽取一颗观察并归位

开启矩阵后，每次自主“注意珍珠”有 50% 概率从矩阵中选一颗（常规活动和反重力漫游都适用），否则选择正式固定珠观察；没有固定珠时只从矩阵选择。此概率是观察活动内的分配比例，不增加观察频率；暂存于 `OracleBehavior.MATRIX_OBSERVATION_SHARE`。矩阵选择使用独立随机流，避免连续选中同一槽位。调试按钮“抽取矩阵珠一次”可直接检查，原有“靠近 / 召近 / 绕珠观察一次”仍针对单珠。

流程为“注意 → 召近 → 保持观察 → 返回槽位 → 停留/继续漫游”。观察距离、时长和低概率睁眼沿用单珠规则；头部与躯干跟踪实际被选中的珠子。矩阵同时最多一颗离队，其原槽位保持空缺，其余珠子不补位；离队珠子的颜色与字符始终不变。重复点击继续使用已抽出的珠子。

归位点随矩阵真实位置更新，中途移动或绕角不会送回旧位置；取消观察、切换到单珠、开始其他手动行动后，离队珠子仍继续归队。只在珠子与矩阵都停稳且位置重合时并回整组采样。路径包含珠体与右上字符投影的余量，重规划至多每 12 tick 一次。调试曲线开启时，金色十字为保留槽位，金色虚线为离队珠子的路线。

关闭矩阵会结束正在进行的矩阵观察，保留自主与漫游选择，不打断单珠观察。重置或工作区尺寸变化会把所配置数量的珠子重新安置在有效矩阵中，清除旧观察路径；工作区重建保留颜色、字形及选择随机流。暂停冻结全部珠子。归位后恢复整组更新与静止缓存，只有离队珠子使用额外的独立运动状态。

| 预览比例 | 默认固定 1×，另可选固定 2×、4× 或适应窗口；固定倍率按屏幕像素计算 |
| 中键拖动 / 定位人偶 | 固定倍率下平移视图 / 将当前人偶置于视图中央，不移动或重置仿真 |

底座百分比在上下边从左到右、左右边从上到下计算。滑动模式可点击任意一边，路径会通过相邻边绕行；点击中央或屏外位置时，目标投到允许的活动区域。绿色为活动带，较亮的部分为给人偶外形和机械臂可达距离留出余量后的规划走廊。大工作区中，如果活动带深处超出任何底座位置的支撑范围，规划走廊会相应收窄。

固定底座模式仍将目标限制在当前边及底座的可达范围内。主视图默认固定 1×：一个游戏单位对应一个屏幕物理像素，窗口最大化、调整大小或系统 DPI 缩放不会放大人偶。固定 2×/4× 也遵守同一规则；四倍局部检查窗同步抵消系统 DPI 缩放。工具栏、字体等界面元素仍正常遵循系统缩放。

固定倍率下只改变视口范围；场景放不下时可中键平移，或点击“定位人偶”。选择固定倍率时会定位当前人偶，随后相机保持在该位置，不自动追踪；选择“适应窗口”可随时查看完整场景。所有操作只改变视图，不改变世界坐标、运动参数、目标、物理时钟或配色。左/右键取点使用同一套反向坐标变换；放大镜遮住需要点击的位置时，可暂时关闭“局部放大”。

## 阶段 6：一颗珍珠与日常观察

`rw_creature_pet/oracle/behavior.py` 的小型状态机在 40 Hz 固定步长中推进，不读墙钟、不在绘制时抽随机数。身体停稳、姿态收敛后先停留 3～6 秒，再独立选择一项活动，不再让每轮活动都必须以观察珍珠结束。允许跨边且两种低频活动均不在冷却中时，默认选择概率如下：

| 活动 | 默认概率 | 表现 |
|---|---:|---|
| 继续停留 | 24.472% | 再休息 7.5～18 秒；可进入外观休眠 |
| 冥想 | 10.488% | 在当前边稍微收拢、闭眼低头，停稳后保持 30～60 秒 |
| 同边短途漂浮 | 30.59% | 在当前边内选择约 60～160 单位的偏移，受边界裁限后至少 30 单位 |
| 注意珍珠 | 21.85% | 注意约 0.9～1.5 秒，靠近、召近或局部绕珠，保持观察 3.5～6 秒后送回 |
| 反重力漫游 | 7.6% | 当前边内自由漂浮、穿插珍珠观察；默认约 300 秒后完成当前观察并停稳 |
| 移到相邻边 | 5% | 只选择当前边的两条相邻边之一，最多经过共用的一个角 |

跨边目标位于新边靠共用角约 18%～38% 的区段；两个方向都可能被选中，但按路径长度更偏向较近的方向。路径明确经过这个角，不能改走另外三个角或选择对边。完成后至少 60 秒才允许再次随机跨边。固定底座、冷却期中的跨边选项退回长停留；其他活动不重抽签。

可在现有 `[oracle]` 配置表中添加 `cross_edge_probability = 0.05`，取值 0～1，设为 0 可关闭随机跨边。未填写时使用默认 5%，启动和本轮实现均不改写用户 TOML。排除跨边分支后，按 `antigravity_probability`（默认 0.08）分配反重力漫游；余下概率按停留 28%、冥想 12%、同边短途 35%、珍珠 25% 分配。调试窗口的“短途漂浮一次”“移到邻边一次”会接管自主循环，运行一次后停止；邻边按钮不受随机概率或冷却限制，固定底座时禁用。

### 局部绕珠观察与冥想

原版 `SSOracleBehavior.cs:4110` 的 Idle 围绕珍珠约 50 单位处移动，`:4145` 的 Meditate 前往房间固定点、朝下看，`:3153` 在冥想中闭眼。桌面版保留观察与安静停留的区别，使用当前边的可行空间，不使用房间中央坐标或强制走完整圆周。

- 自主珍珠活动在靠近／召近／绕珠之间按 35%／35%／30% 选择。绕珠先靠近约 50 单位，再绕一段弧线，停下保持观察，最后送回当前悬浮点。整个过程仍是同一次观察，只抽一次低概率睁眼；头部持续看向真实珠心。
- `EdgePlanner.local_arc` 分别检查两个方向，从 110° 向 12° 缩短，采用每段不超过 45° 的圆弧 Bezier。所有控制点必须处于同一个边缘走廊，用凸包约束整段路径；弧线半径不靠逐帧裁切来维持。先从附近五个入场点中优先选有绕行余量的位置，抵达后按真实位置再规划一次，不逐帧搜索或重建曲线。空间不足时直接保持观察；固定底座调试也退回原地观察，不把圆弧替换成穿过珠心的直线。
- 绕珠期望速度默认约 30.5～37.3 逻辑单位/秒，仍有曲率、起停和机械臂支撑限制。普通活动只在当前边内绕珠；失重期间沿用同一段漫游的朝向、重力和计时。绕珠时实际珍珠保持不动，跟随逻辑只允许更新虚拟悬浮点，结束时再送回。
- 冥想只向当前走廊深度中间收拢最多 24 单位，设置一次沿身体方向略微低头的目标，并平滑闭眼。身体、底座、珍珠、眼睛与头部视线稳定后才累计 30～60 秒的停留时长；衣袍、手脚、念珠和连接线继续自然收敛，满足原有条件后休眠。不添加呼吸正弦、持续转头或定期抖动来维持动画。
- 冥想在普通自主活动中选择；漫游中的自动珍珠活动也可能选到局部绕珠。漫游中手动触发冥想会保留失重模式与总计时，冥想结束后继续漫游；若此时已到期则恢复重力并停留。手动移动／观察／停止会接管当前活动，暂停冻结所有计时，工作区重建清除旧弧线与冥想姿态并保留随机流。

### 偶发反重力漫游

原作 `SSOracleBehavior.GetToDir`（`SSOracleBehavior.cs:3137`）在 Idle 使用 `investigateAngle`，`Move`（`:4110`）以 `invstAngSpeed=1` 持续改变方向，并可能围绕一颗珍珠移动。`Oracle.cs` 用此方向给第二个身体质点设置目标；`OracleGraphics` 的头、手、脚分别通过连接约束跟随，衣袍的理想网格也在躯干局部坐标系中计算。因此非直立姿态来自整个身体的驱动，而不是只让衣袍飘起。原作 `floatyMovement` 是近目标位置控制分支，不是统一的“开反重力”开关。

原作仍会主动用 `investigateAngle` 引导躯干，并非纯惯性。当前 Bell 的桌面适配进一步减弱这种主动朝向控制，将“失重移动模式”与“珍珠观察活动”分开：

- 开始时只渐变重力和移动响应，不抽取预设侧躺角度。朝向控制读取上一帧真实身体方向；上身更快跟随导航，下身少接受一部分移动前馈，靠身体连接逐渐跟上。转弯和速度变化会产生朝向变化，静止且无观察目标时不会主动转动。
- 观察期间仍由独立头颈承担主要转头，身体只受到面向珍珠的轻微转矩。自由朝向不强制靠近竖直方向，也不限制在固定的侧躺角区间；每 tick 最多约 0.86° 的角位移，保留身体连接长度及头尾身份。跨 ±180° 时角度连续。
- 开始约 3 秒逐渐减弱衣袍和项链的向下重力至常态的 4%。双手保留少量画面向下偏置、沿身体方向的力和左右外展力；头部继续独立定长连接，双脚沿躯干方向惯性跟随。原作手部的向下力本身不乘房间重力，这里的渐变是 Bell 桌面效果的适配。连接线仍沿用现有重力和底座出线方式。
- 通常在当前边内选择局部目标，沿边方向每段约 60～100 单位，同时改变走廊内的深度。巡航基准独立于视觉失重程度，默认每段选取 32～48 逻辑单位/秒；保留底座滑动、可达距离和加减速控制，珍珠继续按跟随矩形调整悬浮点。
- 漫游也可低概率跨到两条邻边之一：在到达局部路线终点、准备选择下一段时，沿用 `cross_edge_probability`（默认 5%）抽取，抽取至少间隔 20 秒；到达邻边后共用 60 秒跨边冷却。设为 0 同时关闭普通活动与漫游的随机跨边。优先考虑距离较近的共用角，保持漫游速度；整段路线只经过起点边和目标邻边，不绕到对边。仅这次跨边临时开放两条身体走廊，到达后以新边继续局部漂浮、观察及珍珠跟随。
- 第一次经过约 12～24 秒后，在当前小段路线到达时注意珍珠；观察结束后再等约 20～40 秒选择下一次。复用“靠近或召近 → 观察 → 送回”的活动，失重强度和总计时不会因此重置。靠近和召近时不同时选择随机移动目标，完成后继续漂浮。原有每次观察小概率睁眼的规则仍然有效。
- 漫游阶段默认以 300 秒为中心、随机浮动 ±10%（270～330 秒）。跨边不重置失重强度或总计时；途中到期则先完成本次过角，自动珍珠观察也等到抵达后再触发。到期后完成正在进行的观察和送回，再停止选目标、恢复视觉重力，并从实际身体方向沿较短路径平滑回正。沿用每 tick 最大 0.6° 的角速度及 0.06° 的角加速度；身体与姿态都停稳后才进入普通停留。普通活动重新以直立为基准，调试窗口手动设置的基础倾角仍有效。退出漫游后至少等待 120 秒才允许再次自主触发，手动中断也重新计时。
- 失重时点击“靠近观察一次 / 召近观察一次”会立即执行该分支并继续本段失重模式；过角中手动观察或冥想会按人偶的实际位置确定当前边，不回拉到出发边。点击场景中的移动/观察点、停止、关闭自主行为可以中断整段模式，同时从当前姿态平滑回正。漫游中的观察、冥想和跨边不会触发回正。暂停冻结整个活动。工作区尺寸变化仍采用整组重建，恢复直立有效位置并保留漫游冷却。

可在现有 `[oracle]` 表内添加 `antigravity_probability = 0.08`（0～1）；设为 0 关闭随机漫游，调试按钮仍可使用。`antigravity_duration_seconds = 300.0` 设置漫游时长中心值（至少 1 秒），未填写也默认约五分钟，包含穿插的观察时间，不包含到期后完成当前观察、过角及停稳的时间。两项默认值在 `oracle/config.py`，冷却、跨边抽取间隔与观察间隔在 `oracle/behavior.py`，观察转矩、角速度上限和重力渐变在 `oracle/pose.py`。上下身的移动响应在 `oracle/scene.py`。概率按每次符合条件的选择计算，不是每帧或每秒触发概率。

每轮局部漂浮出发时，先选择连续移动的时间预算：65% 取约 4～10 秒，35% 取约 12～24 秒。在预算内，允许安全地接续下一段曲线；起始切线与旧曲线末端一致，已有引导点和速度不重置，原终点成为途经点。预算到期时在下一处终点减速，不在半路硬停；急转、掉头、边界或观察时机可以提前结束这一轮，因此这不是实际运动时长的硬保证。只缓存尚未走完的曲线，普通漫游至多两段，不积累历史路径。

停顿采用三档分布：短暂犹豫 0.35～1.2 秒、普通停留 1.8～5.5 秒、偶尔长歇 7～14 秒，基础权重为 50% / 35% / 15%。长歇后下一次只从前两档选择，避免连续久停。开始漫游的等待为 2.5～5 秒，观察／冥想／跨边后恢复局部漂浮的等待为 0.5～3 秒。时间只在行动切换时抽取一次，等待期间不重抽、不重新规划；观察到期与漫游到期可以提前打断等待。固定底座调试也使用随机停顿；空间不足时隔 1～4 秒重试目标。参数集中在 `OracleBehavior.DRIFT_ENTRY_TICKS`、`DRIFT_RESUME_TICKS`、`DRIFT_PAUSE_BANDS`、`DRIFT_PAUSE_WEIGHTS`、`DRIFT_BOUT_BANDS`。

停走节奏使用独立的 `timing_random`，与路线、速度、观察／跨边的随机流分开；工作区重建保留随机流但清除旧路径与计时，重置仍可重复对照。长停顿只暂停选择目标，身体、衣袍与线缆继续收敛，只有真正稳定后才休眠；不会为了休息强行冻结姿态。暂停不消耗任何行为计时，手动操作仍可接管。本次没有新增 TOML 字段。

### 珍珠随人偶迁移悬浮点

跟随矩形以人偶的上身质点为中心，默认宽 360、高 280 逻辑单位，保持屏幕水平／竖直方向，不随身体侧倾旋转。同边小范围活动时，悬浮点保持原位；超出矩形后，悬浮点向内收一段，珍珠再沿曲线追上。跨边时，悬浮点还必须与人偶处于同一条安全走廊，防止虽然距离较近，却隔着中央禁区的内角留在旧边。角落重叠区允许两条相邻走廊。

这是柔性跟随范围：虚拟悬浮点始终处于范围内；珍珠的实际位置在加速和绕角期间可以暂时落在框外，停稳后回到框内。不会瞬移、硬裁真实位置，也不会把整条珍珠路径变成穿过中央区的直线。观察期间可以更新虚拟悬浮点，但珍珠的实际目标由观察状态机控制；送回或手动取消时使用更新后的悬浮点。

在已有 `[oracle]` 表中可选添加以下字段；不填写时直接使用默认值，两项均至少为 160。它们随桌宠本身的缩放一起显示，不受调试窗口大小影响；本轮未改写用户 TOML。

```toml
pearl_follow_width = 360.0
pearl_follow_height = 280.0
```

`PearlState.FOLLOW_INSET = 64` 控制超距后内收的距离（不超过对应半边长的 40%），`REPLAN_TICKS = 12` 保证跟随路径最多每 0.3 秒重建一次。新路径继承速度和牵引前置距离；追赶速度上限为 2.4 单位/tick，普通召近和送回仍为 1.6。珍珠的过角点靠近安全走廊内角，保留 16 单位余量，避免为机械臂预留的走廊中线导致珠子先向外绕远；身体的路径规划参数不变。

单珠跟随逻辑放在 `PearlState` 中；可选矩阵使用整组锚点，抽出观察的珠子归位时追踪保留槽位。调试窗口开启“显示规划曲线”时显示灰色跟随矩形与悬浮点十字，桌面模式不绘制这些标记。静止后不重规划、不改珍珠修订号，也不唤醒人偶／衣袍／线缆缓存。工作区重建、手动悬浮点和重置均使用同一套范围约束。

### Bell 默认闭眼

## 阶段 4 的路径和支撑协调

路径规划把四边看作互相重叠的安全走廊，选择相邻角落连接，使用 Bezier 圆滑折角。同边移动也使用受限的曲线。每条曲线递归检查控制点凸包是否完整落在安全走廊内，不能仅检查起点和终点；身体实际移动的线段也检查中央区域，覆盖绘制插值。

身体中心预留至少 36 单位外形边距，覆盖头部附件、独立观察和倾斜时的衣袍与手脚。机械臂杆件也避开中央区域；跨角杆件采用角点外侧切线修正，避免把关节突然投到另一条边。小场景配长机械臂时允许更深折叠，保持关节连续。绘制不靠裁掉进入禁区的身体像素来隐藏越界。

底座轨道内缩 18 单位，圆角半径最大 32。轨道参数为实际弧长，矩形的长边和短边不会出现不同的线速度；底座法线随圆角连续变化，人偶仍保持自己的躯干姿态。底座追随路线前方的一小段，身体根据剩余支撑距离减速，必要时等待底座。

底座启动阈值为 `min(80, 可达半径 × 0.3)`，停止阈值为启动值的四分之一；目标沿轨道变化不超过 12 单位时不更新底座目标。一般要求方向稳定 20 tick 才启动或反向，接近支撑极限时允许提前启动。反向先减速，不直接翻转速度。

以下可选字段加在已有的 `[oracle]` 表内；旧配置不写这些字段也会使用默认值。本次实现没有改写用户的 TOML 或配色。

| 配置字段 | 默认值 | 作用 |
| --- | --- | --- |
| `sliding_base` | `true` | 启动时开启四边滑动；窗口内也可切换 |
| `float_speed` | `1.6` | 普通移动基准速度，单位/tick；允许 0.3～2.0；自主行动按距离和目的调整 |
| `drift_speed` | `1.0` | 失重漫游基准速度，单位/tick；允许 0.3～1.8；每段浮动 ±20% |
| `base_speed` | `2.8` | 底座最大速度，单位/tick；允许 1.5～4.0 |

固定 40 Hz 下，手动普通导航默认为 64 单位/秒、漫游每段为 32～48 单位/秒、底座上限为 112 单位/秒；实际速度会受起停、弯曲程度和支撑距离影响。导航代码在 `rw_creature_pet/oracle/navigation.py`，场景协调在 `rw_creature_pet/oracle/scene.py`。配置中的数值均为逻辑单位，不随系统 DPI 改变；用户 TOML 未填写新增字段也直接采用默认值。

本阶段完成常态人偶外观。原作 `Halo` 属于房间背景层的大范围工作效果，`MoonSigil` 的透明度由工作/对话状态驱动；这两项工作特效没有作为常亮装饰套到桌宠身上，待后续行为阶段决定触发方式。没有引入损坏 Moon（SL）的断线或披风贴图。

### 连接线的受力与活动区约束

粗线保留底座供线点和第 60 点的机械臂导向，释放原来的第 27、53、79 点。供线长度根据合法绕行路径加适量松弛余量平滑调整；路径只决定初始化与可用线长，不作为逐点追踪目标。底座到导向点的余量为 `min(36, 路径长×0.18+12)`，最低总长 65；导向点之后最低长度为 190（原版 19 段×10），路径更长时增加 `min(32, 路径长×0.20+12)` 的余量。供线参考机械臂到身体的路径，不追踪自由末端，以免下垂后继续放线。末端超过距上身 80 后，每 tick 按超出量的 0.25 柔性拉回一次，再求解绳长；允许小幅越界，不硬钉在圆周上。

粗线使用向下 0.20、速度阻尼 0.86，细线使用向下 0.16、阻尼 0.82。相邻绳点保持各自的目标间距，多尺度最大长度约束只传递拉力，避免长链的前几节被快速移动的底座拉长。粗线起点附近按底座出线法线获得小幅出线偏置；细线在分线端和头部端保留方向引导。14 根细线恢复原版混合分布：一半概率取 50～65，另一半取 `50+150×随机数^1.5`；按原版 20 节点/19 段折算，目标总长为参数的 0.95 倍。当前本地固定种子选得约 50.14～182.50，包含少数显著较长的垂线；该种子不等同于 Unity 随机序列。颜色和头端方向在创建时固定，重置可重复。短线先补足两端必需跨度并保留 2 单位余量，额外松弛和回收仍平滑进行，防止分线端快速移动时只拉长末段。

粗线不再做中央禁区的逐点、逐段及帧间扫掠检查；人偶和机械臂仍严格保持在活动带内，软线允许局部自然探出。屏幕外沿依靠窗口裁剪。细线取消上身半径 32 的逐点投影，以绳长与两端连接自然限制覆盖范围；分线端使用上述柔性拉回。绘制主线采用 2.4 宽的深色线芯，双层 `CentipedeSegment` 使用原版 0.8 比例，节距保留用户实机校准的 10（`OracleRenderer.CORD_SEGMENT_SPACING`）；桌面节纹长 7.2，直线段相邻节纹之间保留约 2.8 单位的深色线芯；贴图 X 轴为长轴，两层均直接旋转到线缆切线方向（Qt 的 `atan2(dy, dx)`，不再额外减 90°）；细线宽 1，保留深色、暗红和暗蓝三类。停止后由阻尼收敛，可见位移低于阈值且供线稳定后休眠，移动或观察变化会唤醒。

长度调整前后对照、完整绕行 GIF 和计时可运行 `python tools/oracle/review_oracle_cord_lengths.py`，输出 `oracle-cord-lengths-comparison.png`、`oracle-cord-lengths-preview.gif` 和 `oracle-cord-lengths-metrics.json`；静态对照使用相同缩放与用户当前配色。原有 `python tools/oracle/review_oracle_cords.py` 也可生成完整绕行 GIF、线端近景及测量 JSON；`tests/oracle/test_cords.py` 检查实际受力下垂、停止/唤醒、独立线长、可活动分线端及整圈运动中的拉伸和局部越界幅度。用户自行调整的袖口半宽 5 保持不变。

本轮长线调整通过 16 项相关测试，覆盖最小调试工作区整圈移动、四边起停收敛、插值端点连接、绘制缓存/休眠唤醒、头部与导航隔离。倾斜 25° 时最长细线在约 650 tick 内进入休眠，因此手部测试的整套次级运动观察窗口调整到 700 tick。默认静止姿态：粗线总长约 213.76→307.26，导向点后约 103.18→190，最长细线最低点距头部约 44.33→135.40。默认工作区完整回放仍在 1555 tick 到达，2262 tick 全部休眠；粗/细线最大单段长度误差约 0.47/0.70。最小工作区回归仍要求两者误差小于 1.2，长线自然垂弧不跨越中央。

### 放松时的手部姿态

手部采用 `OracleGraphics.cs:1650–1654`、`GenericBodyPart.Update` 和 `BodyPart.ConnectToPoint` 的更新顺序：先按积分速度移动，应用 0.98 阻尼，再限制到距上身质点 15 以内，继承上身速度（adapt=0.3、exaggerate=0.01），最后加入向画面下方 0.5、沿躯干向下 0.3 和向两侧各 0.3 的受力。向画面下方的分量在完好 Moon 的零重力场景也存在；它不随机械臂底座的边框法线旋转。

不再逐帧追踪原先左右 11、向下 7 的固定放手位置。身体直立且停稳时，双手自然收敛到相对上身左右约 5.27、向下约 14.04；身体倾斜后，两只手在身体局部坐标中不再完全对称。袖子保留肩部向外弯曲的控制点，末端随手垂回衣袍前方。初始化直接使用受力平衡位置，避免重置时突然掉手；移动与停止仍由逐帧受力计算。

`HangingHand.drive_velocity` 保存原版积分速度，`velocity` 保存约束后的实际位移。长度约束会抵消持续向下受力产生的径向运动，因此用实际位移判断停止与休眠，唤醒时保留积分状态，避免手再次掉落或跳动。这一批仅实现常态垂手，不添加对话手势、抓取、受损 Moon 的抱膝或撑地动作。

### Bell 的袖型与睁眼尺寸（暂定）

### 衣袍的动态下垂

`OracleAppearance.step_cloth` 参考 `OracleGraphics.Gown.Update`，保留原版基础宽度与轮廓：衣领固定，其余点只在偏离理想轮廓超过 `9×纵向进度` 时才被拉回。移除每帧追踪理想位置的恢复弹簧，恢复沿画面向下的视觉重力、0.02 的方向偏置，以及按原版顺序从四个相邻点传递的 0.05 连接力。两端都会访问同一条边；静态边长预先缓存，因为整体旋转和平移不会改变理想边长。

桌面没有房间重力状态机，暂用固定 `CLOTH_GRAVITY=0.45`，相当于原版 `0.9×room.gravity` 中的重力为 0.5。`CLOTH_DAMPING=0.90` 比原版 0.999 更快收敛。两者连同 `CLOTH_SLACK=9` 集中在 `rw_creature_pet/oracle/appearance.py` 中，没有新增 TOML 字段。衣袍受力不反馈给身体、手部或机械臂，不改变导航。初始化先放到接近垂坠平衡的位置；从未下垂的轮廓释放也会由实际受力落到相同形态。

`ClothPoint` 分别保存积分速度和实际位移，以实际位移判断停止，休眠时保留积分状态。中线靠上的点可能产生近乎反向的方向插值，这种退化情况使用确定的旋转方向，避免微小浮点误差在 ±π 之间切换，引发停稳后衣袍中部细抖。

所有布点相对上身的距离上限约为 `24.3+9=33.3`，仍落在既有至少 36 单位的外形预留范围内；无需缩减下垂、扩大活动带或裁掉越界部分。三角形和绘制插值也保留这项包围半径。四倍局部检查窗增高到 250×290 并调整居中，完整容纳下摆。

### 连接线性能优化（2026-09-23）

- 保留 80 个主线节点、14×20 个细线节点及现有重力、阻尼、随机个体参数，不改变节点采样密度。移动中主线使用 4～12 遍、细线 2～10 遍长度求解，按误差提前结束。输入停稳后锁住已采用的求解精度，只允许增加到原有上限，避免迭代数反复跳变造成细抖，收敛后休眠。
- 删除软线中央禁区碰撞和扫掠判定，复用数值缓冲区与跨节点连接索引。圆形半径限制先比较距离平方，只在越界时开方。绳索休眠比较容忍 0.001 的输入噪声，并保留累计移动的参考输入。
- 衣袍保持原有按列更新顺序和邻点受力公式，使用标量缓冲区并预先计算局部理想坐标/受力方向；250 tick 对照最大布点位置差约 6.2e-12。
- 渲染器在同一插值帧只准备一次几何、图集引用及绘制指令，主画面和 4× 预览重放同一份数据；调色、重置、插值时间与仿真变化会使缓存失效。1× / 4× 的直接绘制与重放像素检查相同。规划路径也按路线对象缓存。匀速平移时复用人偶局部几何，局部位置变化超过 0.001 时重建；缓存保留参考姿态，累计微小变化仍会触发更新。绘制记录器不持有自引用闭包，旧帧数据能及时释放。
